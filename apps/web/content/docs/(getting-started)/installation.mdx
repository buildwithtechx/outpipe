Choose the client that matches how you work. The CLI is designed for terminals,
automation, and CI. The desktop application provides a graphical control
surface for local tunnel management. They are separate installers and share
the same tunnel protocol.

## CLI installation

### Linux and macOS

```sh
curl -fsSL https://cli.outpipe.dev | bash
```

The installer places `outpipe` in `$HOME/.local/bin` by default. Make
sure that directory is on your `PATH`.

### Windows

Download the Windows release archive from the CLI release page, extract
`outpipe.exe`, and place it in a directory on `PATH`.

### Verify the CLI

```sh
outpipe version
outpipe health --api-url https://api.outpipe.dev
```

## Desktop installation

Download the installer for your operating system from:

```text
https://desktop.outpipe.dev
```

Use the `.deb` or `.rpm` package on Linux, the `.dmg` application on macOS,
or the Windows installer on Windows. Launch the application after installation
and sign in through the browser-based account flow.

The desktop app supervises the Go tunnel client. It does not replace the CLI,
and installing the desktop app does not add a `outpipe` command to
your terminal.

## Private or local installations

Pass the API and relay endpoints through the CLI environment or command
configuration. The client is designed to work with the hosted service and
independent installations of the server.

## Release channels

The branded installer resolves the current CLI release for the host platform.
For pinned builds, download a versioned release artifact and verify its
checksum before placing it on `PATH`. In CI, prefer a pinned release rather
than installing an unreviewed floating version on every run.
