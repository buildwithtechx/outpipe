Outpipe creates an encrypted path between a local service and a public
endpoint. It is an independent product: you can use the hosted service,
self-host the server components, or build on the protocol and SDKs without
using Outpipe.

## Why Outpipe?

- **Independent by design:** Use the hosted service, self-host the server, or connect your own tools without installing Outpipe.
- **One protocol:** The CLI, desktop client, TypeScript SDK, and framework adapters share the same versioned relay protocol.
- **Built for real workflows:** Protect previews, receive webhooks, test OAuth callbacks, and run tunnels inside CI jobs.
- **Operationally visible:** Track connections, bandwidth, request outcomes, and retention through the API and dashboard.

## How a request travels

1. A client authenticates with the Tunnel API.
2. The client opens a protocol session with the relay.
3. The relay associates the session with a tunnel and its organization.
4. A request arriving at the public endpoint is forwarded through the session.
5. The local client sends the request to the selected local target and streams the response back.
